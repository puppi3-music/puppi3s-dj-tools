Tempo view

If you play a set at one tempo with key lock, tempo stretches every scanned track to that tempo with Rubber Band (pitch kept) and analyses it again: genre, moods, colour and hype. You can then switch your DJ app to the view and back. Your normal results are never touched. install rubberband gets the stretcher on Windows.

Before you start

  • Run every command from the project folder, as uv run dj-track-analyzer <command>. See Running a command.
  • The view needs Rubber Band 3.0 or newer. On a Mac: brew install rubberband; on Linux: sudo apt install rubberband-cli; on Windows: install rubberband. The Setup tab's Extra tools card installs it too.
  • Scan your music normally first (scan): the view only takes tracks that have a normal scan.
  • Pick any tempo. The default is 145; add --bpm 140 (or any tempo) to every action except native and status. Each tempo is a separate view with its own data in data/at-<bpm>/, so several can exist side by side. Only one can be loaded at a time.
  • Scanning, reports and files are fine with your DJ app open. Quit it before tempo load and tempo native: they refuse while it runs. Their --dry-run works either way.
  • How to read it. The models learned from tracks at the tempo they were released at. Almost no house was released at 145, so stretched there a rolling house track sounds to them like trance and psytrance. Read the view as how the models hear the sped-up track, not as facts. Psytrance, the worst case, is held back: in the view it counts at most 1.5× what the track had at its own tempo.

On the web page, the Setup tab's Tempo view step scans a view, and the Tempo view tab shows what changes and loads it into your DJ app and back. This page shows browses a view on the other tabs. The guide's Hearing my catalogue at my play tempo walks through it.

tempo scan

Stretches every scanned track to the view tempo and analyses it again.

  • Fine with your DJ app open; reads its collection only
  • Changes: the view's own data in data/at-<bpm>/
  • Needs: Rubber Band, and a normal scan
uv run dj-track-analyzer tempo scan
uv run dj-track-analyzer tempo scan --bpm 140
  • About an hour for 470 tracks the first time. It's resumable: stop it and run it again to carry on. Later runs only take new tracks.
  • It uses Rubber Band's R2 engine, which changes the sound for the models far less than R3. (The page's player uses R3, which sounds best to the ear.)
  • Your colour isn't replaced: in the view it's moved by how far the colour model thinks the track shifts at that tempo. Uncoloured tracks stay uncoloured, and a colour you hold stays as it is.

Options

OptionWhat it doesDefault
--bpm BPMThe tempo you play at. Each tempo is its own view.145
--workers NHow many tracks are analysed at once.half your cores, max 5
--rescanAnalyses again tracks already in the view.off
--nml PATHUses this collection.nml instead of the one chosen on the Setup tab or found automatically.found

tempo report

Prints what changes at the view tempo: genres, colours and hype.

  • Read only, fine with your DJ app open
  • Needs: a tempo scan at that tempo
uv run dj-track-analyzer tempo report
uv run dj-track-analyzer tempo report --limit 30

It lists:

  • genres at own tempo next to genres at the view tempo, and the most common changes
  • your colours at that tempo
  • the tracks that turn hardest or prettiest
  • the tracks with the most hype there, and the biggest hype risers

The Tempo view tab on the page shows the same.

Options

OptionWhat it doesDefault
--bpm BPMWhich view to report on.145
--limit NHow many tracks each list shows.15
--jsonPrints the full result as JSON instead of the report.off

tempo nml

Writes a standalone copy of Traktor's collection.nml with the view's genres, colours and hype in it. Your real collection isn't touched.

  • Fine with your DJ app open; reads its collection only
  • Changes: writes at-<bpm>/collection.nml (or the --out file)
  • Needs: a tempo scan at that tempo
uv run dj-track-analyzer tempo nml

To switch Traktor itself to the view and back, use tempo load and tempo native instead.

tempo load

Switches your DJ app to the view: it then shows the genres heard at that tempo, your colours moved by the shift and the view's hype.

  • Quit your DJ app (not for --dry-run)
  • Changes: your DJ app's collection (backup first); with --lexicon Lexicon's library too
  • Undo: tempo native, or Switch Traktor back to normal… on the Tempo view tab
  • Needs: a tempo scan at that tempo
uv run dj-track-analyzer tempo load --dry-run
uv run dj-track-analyzer tempo load
uv run dj-track-analyzer tempo load --lexicon
  • Per track it changes:
    • Genre: the genres heard at the view tempo.
    • Colour: your colour, moved by how far the model thinks the track shifts (your Blue, one step harder, becomes Green). Uncoloured and held tracks stay as they are.
    • Comment: the "Hype NN" part becomes the hype at that tempo; your own text there stays.
    • Smartlists: "Genres (Track Analyzer)" is replaced by "Genres @145 (Track Analyzer)" (@ the view tempo).
    • Clock tempo (Traktor): set to the view tempo. Tracks follow it only with Sync on and the clock as master.
  • It refuses while Traktor writes tags to your files (Preferences → File Management), because Traktor could write the view's genres into them and native only restores the collection. --force loads anyway.
  • While the view is loaded, hype, stats and export use its data; add --native for each track at its own tempo. Commands that write your own values refuse to run so they can't mix them into the view: traktor, sync, hype --traktor, colors apply, colors train, cues apply, grids apply, edit and others.
  • Works with Rekordbox as your DJ app too (chosen on the Setup tab); it has no clock tempo to switch.
  • --lexicon also switches Lexicon: its genre, colour, comment and Energy (the view's hype, 1–10), plus a "Genres @145 (Track Analyzer)" Smartlist folder. Once: open Lexicon and turn on Settings → Integrations → Local API. Lexicon's library is copied to data/lexicon-backups/ first. While Lexicon has the view, don't sync Lexicon → Traktor or import from Traktor into Lexicon; syncing to a USB is fine.

--forceLoads even while Traktor is set to write tags to your files.off
--lexiconSwitches Lexicon too (Lexicon open, Local API on). If your DJ app already has the view, only Lexicon is switched.off

tempo native

Switches your DJ app back from whichever view is loaded. This is the undo of tempo load.

  • Quit your DJ app (not for --dry-run)
  • Changes: your DJ app's collection (backup first); with --lexicon Lexicon's library too
  • Needs: a view loaded with tempo load
uv run dj-track-analyzer tempo native --dry-run
uv run dj-track-analyzer tempo native
uv run dj-track-analyzer tempo native --lexicon
  • It puts back only genre, colour, Comment and the genre Smartlists, so cue points, plays, History and tracks added meanwhile all stay. The clock always goes back to your tempo.
  • A genre, colour or Comment you changed yourself while the view was loaded is kept, and listed under kept.
  • If Lexicon still has the view, it says so: run it again with --lexicon. With --lexicon both are switched back, a Lexicon field only where it still holds the view's value.
  • Backups are named collection.nml.before-tempo-view-…; traktor --undo ignores them. Don't delete data/tempo-loaded.json while a view is loaded: it holds your own values.

Options

OptionWhat it doesDefault
--dry-runShows what would be put back without touching anything.off
--lexiconSwitches Lexicon back too (Lexicon open, Local API on).off
--nml PATHUses this collection.nml instead of the one chosen on the Setup tab or found automatically.found

tempo refresh

Works out the view's genres, colours and hype again from what the scan measured, without listening again. Takes seconds.

  • Fine with your DJ app open
  • Changes: the view's own data
  • Needs: a tempo scan at that tempo
uv run dj-track-analyzer tempo refresh

Run it after editing dj_genres.json or retraining colours. colors train with --refresh-views does it for every view.

Options

OptionWhat it doesDefault
--bpm BPMWhich view to refresh.145

tempo status

Says which view is loaded in your DJ app and in Lexicon, and lists the views scanned so far with their track counts.

  • Read only, fine with your DJ app open
uv run dj-track-analyzer tempo status

The Traktor tempo view and Lexicon tempo view labels at the top of the web page show the same. No options.

install rubberband

Installs Rubber Band, the time-stretcher the tempo view needs. On Windows it downloads Rubber Band's own build.

  • Fine with your DJ app open
  • Changes: puts the program in data/tools/rubberband/
  • Needs: Windows and an internet connection
uv run dj-track-analyzer install rubberband
  • The download is checked against its known SHA-256 before anything is installed.
  • On a Mac or Linux it installs nothing and prints the command to run instead: brew install rubberband, or sudo apt install rubberband-cli (or your distribution's package manager).
  • The Setup tab's Extra tools card does the same (on Linux it shows the command).

Options

OptionWhat it doesDefault
TOOLThe tool to install. Only rubberband for now. Needed.none
