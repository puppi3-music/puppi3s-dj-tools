The app itself

web opens the web page, or saves a read-only snapshot of it to share. serve runs the MCP server, so a local LLM (LM Studio, Open WebUI) can search your collection. update installs the newest release, and goes back again if it doesn't suit you.

Before you start

  • Run every command from the project folder, as uv run dj-track-analyzer <command>. See Running a command.
  • The launcher (Start Puppi3's Track Analyzer.command on a Mac, .bat on Windows; on Linux, run the .command file from a terminal) does the same as web, and also starts the page again after an update.
  • Most of the page and the LLM's answers come from your scan: scan first.
  • All three are fine with your DJ app open.

The guide's Open the web page, Asking a local LLM and Updating the app walk through them on the page.

web

Starts the web page on this computer and opens it in your browser: Overview, Tracks, Hype, Colours, Tempo view, Mixes, Files and Setup. Leave the terminal window open while you use it; Ctrl-C stops it.

  • Fine with your DJ app open
  • Changes: nothing while you browse; only buttons that say so write (holds, cue approvals, saved samples, the Setup tab's writers), with a preview first
  • Needs: a scan for most tabs; saved mix analyses in logs/ for the Mixes tab
uv run dj-track-analyzer web
uv run dj-track-analyzer web --no-open --port 8800
uv run dj-track-analyzer web --export snapshot.html
  • The page is at http://127.0.0.1:8766/. It answers only this computer's own names, so another web site can't reach it.
  • --host 0.0.0.0 opens it to other devices on your network. It has no password: only on your home network, and never port-forward it.
  • --export FILE.html saves the whole page as one HTML file with the data inside, instead of serving it: it opens in any browser, offline, and can't change anything. It includes track names, file paths, playlists and play counts. On the page this is Export snapshot, top right.
  • --logs picks the folders whose saved JSON the Mixes and Files tabs show.

serve

Runs the MCP server: a local LLM can then analyse a track or folder, search your collection, suggest what mixes with a track, give the collection's numbers, list your genres and train your own genres. On its own it talks over stdio, which is what LM Studio starts; with --http it serves streamable HTTP for Open WebUI.

  • Fine with your DJ app open
  • Changes: nothing in your files or DJ app; training genres from the chat saves your genre model
  • Needs: a scan; the LLM app set up once (README section 8)
uv run dj-track-analyzer serve --http
uv run dj-track-analyzer serve --http --host 0.0.0.0
  • LM Studio starts the server itself: in its mcp.json, command is the full path of uv and args are run --directory <project folder> dj-track-analyzer. You don't run serve by hand.
  • Open WebUI: run serve --http and leave the window open, then add an MCP (Streamable HTTP) tool with the URL http://127.0.0.1:8765/mcp (in Docker on the same computer: http://host.docker.internal:8765/mcp; on another machine: this computer's LAN address).
  • --host 0.0.0.0 is needed for Open WebUI in Docker or on another machine. The server has no password: only on your home network, and never port-forward it.
  • File paths are paths on the computer running the analyzer.
  • Use a model that's good at tool calling. The README's section 8 has the full setup for both.

update

Installs the newest release and prints what it did as JSON. Your data/ folder (scans, models, training, settings), logs/ and the installed packages aren't touched. Every file it replaces is backed up first, so --undo goes back to the version you had.

  • Fine with your DJ app open
  • Changes: the app's own files; backups in data/app-backups/
  • Needs: an internet connection
uv run dj-track-analyzer update --check
uv run dj-track-analyzer update --dry-run
uv run dj-track-analyzer update
uv run dj-track-analyzer update --undo
  • --check only says whether a newer release is out, and what's new.
  • The release's download is checked against its checksum before anything is written; if it fails halfway, the old version is put back at once.
  • After an update, start the analyzer again (its launcher, or web) to use the new version. From a terminal, then run uv sync --inexact and setup for new packages and models; the guide's Updating the app lists the steps a release can need after that.
  • Which builds you get follows the Setup tab's Updates: Stable / Dev: Stable installs only finished releases, Dev also the newest work in progress. It never goes back to an older version on its own.
  • In a git clone it runs git pull on main, only without changes of your own; --undo goes back to the commit it was on. In Docker, build the image again instead.
  • On the page this is the Setup tab's Update now… and Go back to ….

Options

OptionWhat it doesDefault
--checkOnly says whether a newer release is out, and what's new.off
--dry-runShows what would change, changes nothing. Works with --undo too.off
--undoGoes back to the version before the last update.off
