Library and analysis

The commands that get the models, analyse your tracks and show what came out: setup, scan, analyze, stats, export, keys and styles. Every other area builds on a scan.

Before you start

  • Run every command from the project folder, as uv run dj-track-analyzer <command>. See Running a command.
  • Run setup once first: scan refuses until the style models are there.
  • None of these change your DJ app, so they're all fine with it open. Quit it before scan --traktor if you've just added tracks, so its collection is saved.
  • The app keeps its results in its data/ folder: collection.db (the scan), collection.csv (the spreadsheet) and models/.
  • scan, analyze and keys always work on each track at its own tempo. stats and export use the loaded tempo view while one is loaded; add --native for the normal library. Each says on its first line which library it uses.

On the web page, the same things live on the Setup tab (models, Scan) and the Tracks tab.

setup

Downloads the models the analysis uses, then checks the genre rules (as styles does).

  • Fine with your DJ app open
  • Changes: the app's files only (data/models/)
  • Needs: an internet connection, once
uv run dj-track-analyzer setup
  • Files already downloaded are skipped, so running it again only fetches what's missing.
  • The MAEST genre model is a few hundred MB. Without it the genres rely on the other style model alone.
  • When the model site (essentia.upf.edu) can't be reached, it lists each file's address and the folder to put it in. Download them in a browser, move them there, and run setup again to check.

Options

OptionWhat it doesDefault
--no-maestSkips the larger MAEST genre model.off

scan

Analyses a whole collection and saves the results: BPM, key, genre, moods, colour and more per track, in the app's database and a spreadsheet.

  • Fine with your DJ app open
  • Changes: the app's files only, unless --write-tags
  • Undo for tags: untag
  • Needs: setup
uv run dj-track-analyzer scan --traktor 2>&1 | tee logs/scan.txt

Tell it what to scan: --traktor for every track in every DJ app found (Traktor and Rekordbox), one or more folders, or both:

uv run dj-track-analyzer scan "/path/to/Music"
uv run dj-track-analyzer scan --traktor "/path/to/New tracks"
  • It's resumable. Ctrl-C stops safely; run the same command to carry on. Tracks already scanned are skipped unless the file changed, and tracks that failed last time are tried again.
  • Each line shows the progress and the time left. A first scan takes a while; later ones only analyse what's new.
  • Traktor's own mix recordings and samples folders are left out, and so are Syncthing conflict copies (*.sync-conflict-*), which are the same tracks twice.
  • Results for files that no longer exist, or are now in an excluded folder, are removed.
  • At the end it writes the spreadsheet and prints the same summary as stats.

Options

OptionWhat it doesDefault
--traktorScans every track in every DJ app found (Traktor and Rekordbox). Works together with folders.off
--nml PATHReads this collection.nml instead of the one found automatically.found
--exclude FOLDERLeaves this folder out. Repeat for several.none
--include-recordingsAlso scans Traktor's own mix recordings.off
--workers NHow many tracks to analyse at once.half the cores, at most 5
--rescanAnalyses every file again, even ones already scanned.off
--write-tags FIELDSAlso writes results into the files' own tags: any of genre, bpm, key, camelot, comma-separated (key or camelot, not both). The old tags are backed up first, so untag restores them.off

Examples:

uv run dj-track-analyzer scan --traktor --exclude "/path/to/Old stuff"
uv run dj-track-analyzer scan "/path/to/Music" --write-tags genre,bpm,camelot

To write genres into the tags later, with more control, use tag instead.

analyze

Analyses one file and prints the result as JSON. Nothing is saved to the collection.

  • Read only, fine with your DJ app open
  • Changes: nothing, unless --out
  • Needs: setup
uv run dj-track-analyzer analyze "/path/to/track.mp3"
  • To get the path: in Finder, hold Option, right-click the file and choose Copy "…" as Pathname. On Windows: Shift + right-click → Copy as path. On Linux, drag the file into the terminal. Keep the quotes.
  • The JSON holds the BPM and how sure it is, the key and Camelot, the DJ genre and the Discogs styles behind it, your own genre if you trained one, moods, loudness, instruments, how much of it has vocals, the colour, and the energy curve.
  • Files over 12 minutes are treated as DJ mixes: they get a timeline in 2-minute steps, and a readable summary after the JSON.

Options

OptionWhat it doesDefault
--segments SECONDSAdds a timeline in steps of this many seconds (60 for 1-minute steps).none; 120 for a mix
--out FILE.jsonSaves the JSON in this file instead of printing it. The file is replaced once the analysis is done.printed
--json-onlyFor a mix: leaves out the readable summary after the JSON.off

Recorded mixes

The rest of analyze's options are for your own recorded mixes: checking one against what you played, YouTube chapters, clip suggestions and standalone pieces. They're explained on Mixes and clips. They are --tracklist, --start, --chapters, --offset, --highlights, --clip-length, --clip-mood, --no-standalone, --standalone-separate, --standalone-pairs-only and --no-solo-rework.

stats

A summary of the scanned collection, as JSON.

  • Read only, fine with your DJ app open
  • Needs: a scan
uv run dj-track-analyzer stats
FieldMeaning
tracksHow many tracks are scanned.
errorsHow many failed to analyse. Scan again to retry them.
last_scanWhen the last scan ran.
avg_bpm, bpm_histogramThe average BPM, and how many tracks fall in each BPM range.
top_camelot_keysThe most common keys, in Camelot.
genresTracks per genre.
coloursTracks per colour.

Options

OptionWhat it doesDefault
--nativeUses the normal library even while a tempo view is loaded.off

export

Writes the scanned collection to a CSV spreadsheet, one row per track. scan already does this at the end; use export for another copy, or for a tempo view's values.

  • Fine with your DJ app open
  • Changes: the spreadsheet file only
  • Needs: a scan
uv run dj-track-analyzer export
uv run dj-track-analyzer export "/path/to/collection.csv"

Without a path it writes data/collection.csv. To open it: open data/collection.csv on a Mac, start data\collection.csv on Windows, xdg-open data/collection.csv on Linux.

Options

OptionWhat it doesDefault
PATHWhere to write the spreadsheet.data/collection.csv
--nativeUses the normal library even while a tempo view is loaded.off

keys

Measures the key with the MusicalKeyCNN model for scanned tracks that don't have one yet, and compares it with Essentia's key and Traktor's.

  • Fine with your DJ app open
  • Changes: the app's database only
  • Needs: a scan
uv run dj-track-analyzer keys
  • New scans measure this key already. keys fills it in for tracks scanned before, and can be stopped and run again.
  • The report starts with how many tracks have a CNN key. Then, per comparison, how often the keys are the same, the MIREX score (partial credit for close keys), and how often they differ by a fifth, as relative or parallel keys, or otherwise.
  • Last comes a list of the least confident CNN keys next to Essentia's and Traktor's. Those are the tracks worth checking by ear.

Options

OptionWhat it doesDefault
--rescanMeasures every track again, not only those without a CNN key.off
--workers NHow many tracks to measure at once.all cores but two
--show NHow many of the least confident keys to list.20
--jsonPrints JSON instead of the report.off

styles

Lists the 400 Discogs style names the genre model knows, then checks the genre rules in dj_genres.json against them.

  • Read only, fine with your DJ app open
  • Needs: setup
uv run dj-track-analyzer styles
  • Use it when you edit the genre rules: each DJ genre is made from Discogs styles, and a misspelled style is ignored. The last line says how many DJ genres there are and whether every style name is valid, or names the ones that aren't.
  • Your own copy in data/dj_genres.json wins over the built-in one. After editing it, regenre works out the genres again without a new scan.
  • How styles become DJ genres: From styles to DJ genres in the guide.

No options.
